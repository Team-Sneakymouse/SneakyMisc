## Agent Brief

**Category:** bug
**Summary:** Make SneakyMisc safe with SneakyPocketbase async loaded callbacks and main-thread-only MagicSpells access

**Current behavior:**
Leaderboard periodic sync runs on an async Bukkit scheduler thread while reading MagicSpells variables, online accounts, and character/account state. SneakyPocketbase loaded callbacks now run on Pocketbase's async scope, so any callback path that touches Bukkit or MagicSpells state needs to be main-thread safe. Registration also keeps a Pocketbase-backed account cache that is accessed from async callbacks.

**Desired behavior:**
SneakyMisc should keep Bukkit, MagicSpells, and character/account state reads on the Bukkit main thread. Expensive or blocking Pocketbase reads/writes should remain asynchronous. Existing behavior should be preserved: leaderboard values are collected from configured variables, writes are debounced, displays are updated from realtime/cache state, DClock Pocketbase sources subscribe and refresh, and registration checks continue to use the Pocketbase account cache.

**Key interfaces:**
- Leaderboard periodic sync should collect Bukkit/MagicSpells/character snapshots on the main thread before performing Pocketbase updates asynchronously.
- Leaderboard score updates should not capture mutable Bukkit or character objects into async Pocketbase work when immutable values are enough.
- DClock Pocketbase subscription and cache refresh should be reviewed under the async loaded-callback contract; any Bukkit or MagicSpells-sensitive work must run on the main thread.
- Registration's Pocketbase-backed account cache should be safe when updated/read from async event paths.

**Acceptance criteria:**
- [x] Leaderboard periodic sync no longer reads MagicSpells variables, online accounts, or character/account state from an async scheduler thread.
- [x] Leaderboard sync still collects configured leaderboard values, debounces unchanged values, and writes Pocketbase records asynchronously.
- [x] Leaderboard display updates still happen on the Bukkit main thread.
- [x] DClock's loaded-callback path is reviewed and contains no Bukkit/MagicSpells-sensitive work on the Pocketbase async callback thread.
- [x] The unused `MSVariableSync` import is removed unless there is a concrete reason to keep it.
- [x] Registration's Pocketbase-backed account cache is safe for its async update/read paths.
- [x] The project builds and tests against the current SneakyPocketbase jar.
